# digital-project-cover

## 目标

创建一个新的 skill，让用户只输入一个中文文章标题，就能直接生成一张固定模板风格的「数字项目部」封面图。

第一版的目标不是做“通用 AI 海报生成器”，而是做一套稳定、可重复、严格复刻参考图气质与版式的封面渲染能力。

默认输出要求：

- 比例固定为 `3:4`
- 分辨率固定为 `2160 × 2880`
- 输出格式为最终 `PNG`
- 用户默认只看到最终成品图，不看到中间提示词或排版草图

## 用户意图边界

这个 skill 只用于下面这类请求：

- 给这篇文章做一张封面
- 根据这个标题直接生成数字项目部封面
- 按这个标题出一张 AI 文章配图
- 做一张和参考模板同风格的封面

这个 skill 不应该用于下面这些场景：

- 设计一个全新品牌视觉系统
- 生成任意风格的宣传海报
- 替用户探索多个封面方向
- 自由修改比例、品牌名、slogan、主题色和整体构图

换句话说，这个 skill 是“固定模板封面渲染器”，不是“开放式封面设计助手”。

## 建议命名

默认使用 `digital-project-cover` 作为 skill 目录名。

理由：

- 与用途直接对应
- 命名足够短，便于触发
- 能和现有技能仓的目录风格兼容

## 固定视觉约束

第一版必须锁死以下视觉约束：

- 背景是浅白灰渐变，不允许变成深色背景
- 右上角固定为渐变胶囊标签 `AI 文章`
- 左上角固定为品牌头图 `brand-header.png`
- 左下角固定展示：
  `数字项目部`
  `用 AI 提升认知 · 用项目创造价值`
- 右下角固定为机器人主体 `robot-cube.png`
- 整体保留轻科技、柔和高光、干净留白和青绿到蓝紫的品牌色系统

第一版明确不支持：

- 改品牌名
- 改 slogan
- 改模板布局
- 改主色体系
- 改输出比例
- 切换成完全不同的封面样式

## 推荐实现形态

第一版采用“固定模板渲染”方案，而不是“每次让模型自由重画一张海报”。

原因：

- 用户已经明确要求“严格复刻”
- 固定模板渲染的稳定性远高于自由生图
- 标题变化只会影响文字区，不会破坏品牌资产位置
- 更适合做成长期可复用 skill

对外体验仍然保持简单：

- 用户输入标题
- skill 自动处理标题
- skill 输出最终封面图

但内部执行必须是确定性的模板组合，而不是开放式创作。

## 渲染架构

第一版建议拆成四个职责单元：

1. `SKILL.md`
   负责触发条件、工作流说明、标题处理规则、失败兜底规则
2. `assets/`
   负责保存固定视觉资产与参考图
3. `scripts/render_cover.*`
   负责把标题、样式规则和固定资产组合成最终 `2160 × 2880` PNG
4. `agents/openai.yaml`
   负责 UI 展示和更好的 skill 发现

渲染引擎应优先选择确定性方案，例如：

- 用脚本生成固定布局画布
- 在固定坐标放置背景、品牌头图、标签、品牌区和机器人主体
- 只对标题区做自动排版

实现阶段可以再决定使用哪种具体技术栈，但架构上必须保证“模板固定、标题可变、其他元素锁定”。

## 标题处理规则

标题是唯一的必填输入。

内部处理流程如下：

1. 读取用户原始标题
2. 做轻量语义切分
3. 自动分成 `3–5` 行
4. 从中挑出 `1–2` 个重点词
5. 为重点词分配更强的样式层级
6. 将结果交给固定模板渲染器

重点词选择规则：

- 优先选动作词、结果词、转折词、结论词
- 如有 `AI`、`Prompt`、`Claude Code` 这类英文技术词，允许单独突出
- 如果没有明显重点词，默认把最后一行作为视觉重点

标题样式分层：

- 普通字：深海军蓝、重磅无衬线、高可读性
- 重点词：青绿到蓝紫渐变
- 超重点词：在不损失可读性的前提下，允许更强的艺术化处理

第一版的优化目标是“像参考图一样有视觉重点”，不是“每次都生成全新书法字风格”。

## 标题过长时的兜底顺序

标题长度不可控，所以必须把兜底顺序写死。

如果标题放不进预留区，按下面顺序依次处理：

1. 先重新分行
2. 再微调字号
3. 再减少艺术字覆盖范围
4. 再微调字距
5. 只有在前面都不够时，才做最小幅度的封面化压缩

“最小幅度的封面化压缩”含义是：

- 保留原意
- 尽量不改措辞
- 只压缩对视觉冗余贡献最大的部分

第一版不应该默认重写标题，更不应该擅自改标题立场。

## 布局规则

版式必须接近参考图的单一模板：

- 左上：品牌头图
- 右上：`AI 文章` 渐变胶囊
- 中上到中部：超大标题区
- 左下：品牌名与 slogan
- 右下：机器人主体与底座空间

其中有三块区域属于锁定区：

- 左上品牌头图区
- 左下品牌区
- 右下机器人主体区

无论标题如何变化，都不能让标题侵占这三块区域。

## 输出规则

默认只输出一张最终封面图。

第一版默认不输出：

- 中间提示词
- 标题分析过程
- 分行草案
- 重点词说明
- 多版本候选图

除非用户明确提出需要调试信息，否则 skill 应保持“输入标题，直接出图”的交付方式。

## 失败与异常处理

第一版需要明确处理下面这些异常情况：

- 标题为空
- 标题过长且超出模板上限
- 必要资产缺失
- 渲染脚本执行失败
- 输出图片分辨率不符

处理原则：

- 标题为空时，先要求补标题，不生成图
- 标题过长时，优先按兜底顺序保守收缩，不直接报错
- 资产缺失或脚本失败时，要明确指出是本地渲染失败，而不是返回半成品
- 如果最终导出尺寸不是 `2160 × 2880`，应视为失败而不是凑合交付

## Frontmatter 与触发描述

`SKILL.md` 的 frontmatter description 需要明确表达：

- 这是一个把中文文章标题渲染成固定模板封面的 skill
- 适用于数字项目部这套品牌封面
- 默认输出 3:4 超清图片
- 重点是固定模板与稳定复刻，不是自由设计

同时也要明确写出它不适合：

- 通用海报设计
- 多风格探索
- 无品牌约束的图片生成

## 验证计划

第一版的验证至少包括：

1. 用一个短标题测试是否能正常生成 `2160 × 2880` PNG
2. 用一个中等长度标题测试是否能正确分成 `3–5` 行
3. 用一个较长标题测试兜底顺序是否生效
4. 人工核对生成图与参考模板在布局上是否一致
5. 人工检查左上品牌头图、右上标签、左下品牌区、右下机器人区是否都稳定保留
6. 人工检查是否只替换标题，而没有意外改动固定文案

## 非目标

第一版不做下面这些事：

- 不做多模板系统
- 不接入自由生图工作流
- 不支持用户自定义品牌
- 不支持切换不同 slogan
- 不支持自动生成多张候选图供选择
- 不把它扩展成任意公众号封面生成器

## 实现备注

实现阶段有两个现实约束需要提前记住：

- 当前没有单独的左上透明 logo 资产，因此需要先生成或整理 `brand-header.png`
- 当前机器人图来自单张参考图，可能需要清理背景后再作为最终资产使用

如果实现时发现字体、艺术字效果或透明边缘处理存在技术限制，优先保证下面三件事：

1. 模板布局稳定
2. 标题可读
3. 品牌资产位置正确

这三个目标优先级高于“完全复刻示例中的每一笔艺术字纹理”。
